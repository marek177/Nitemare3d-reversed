Existing synthetic caller frame has zero cumulative wordBP-4; second subtraction operandBP-6 zero. InputDX0 allows each selected WORD request length without pointer addition overflow. Original source pointerBP+8 is6000, whose first byte is independently varied. The OS stub does not consume that potentially large request buffer; it returns selectedAX andCF. Therefore these fixtures establish instruction behavior, not actual device buffer semantics.

The helper's zero-success path performsCMP(request,0), thenLAHF savesSF/ZF/AF/PF/CF intoAH. SAHF restores flags but does not restore the previousAH. The device/first-byte tests do not changeAX. CLC then passes to3D41, which takes its success branch. Its stack epilogue also does not changeAX. Thus the finalAX is the saved flag byte shifted8, not zero. Examples:request1→0200,request3→0600,request20→0600,request8000→8600. Pass53 verifies each selected request across all byte/device/error combinations. On the Ctrl+Z success path errno085E and raw error086E remain unchanged. SP,BP,DS,SI,DI and finalAX checked. CF is captured at3D41 before its later stack arithmetic can change flags; no claim is made that the final far-returnCF equals that capturedCF.

## Implementation-ready findings
For5902 text mode, count CR insertions and subtract them from the physical successful write sum. Keep direct byte-output mode separate. Model zero-progress handling with its exact descriptor/first-byte guard; a blanket return0 for Ctrl+Z is not instruction-equivalent. Preserve the residualAH only when reproducing this exact CRT path. Do not infer that every game file write or OS device reaches it.
