## Behavior model
`8604(heading, flagWORD, countSIGNED_WORD, nearOutX, nearOutY)` is far cdecl. DS=SS in this fixture. It copies DS:4BF6/4BF8 to outputs; count<=0 performs no collision calls and leaves error unchanged. The routine does not compute sine/cosine or reseed the error. Inputs 4C06/08/0A/0C were derived from original EXE quarter tables using the pass117 model.

For each positive iteration:
1. Query major axis and add returned AX to its output WORD.
2. If signed error<0, add increment4C0A. Otherwise add diagonal increment4C0C and query the other axis, then add that return value.
3. Repeat count times. All coordinate/error additions wrap to WORD. Primary movement can alter coordinates used by the subsequent minor query.

Collision address construction (all final offsets truncated to WORD):
- `qx(v)=signed16(word(v)&FFDFh) >> 5` using arithmetic shift.
- `qy(v)=word(v)&FFC0h`, then double with WORD wrapping.
- X query: first offset=A69Eh+qx(x+28*dx)+2*qy(y-27*dy), second=A69Eh+qx(x+28*dx)+2*qy(y+27*dy), direction=dx.
- Y query: first offset=A69Eh+2*qy(y+28*dy)+qx(x-27*dx), second=A69Eh+2*qy(y+28*dy)+qx(x+27*dx), direction=dy.
- Both selectors normalize to 1040h (NE segment9). These addresses were checked as values; the stub does not dereference them or validate a real map.

## Implementation-ready findings
Preserve error state across movement calls; update it even when collision denies movement. Treat flag as BYTE for inversion, count as signed WORD, addresses/coordinates as WORD, and error sign checks as signed WORD. Keep the major-first query order. Model 84F4 and 8A20 separately before claiming complete player movement parity.
