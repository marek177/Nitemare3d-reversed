# Nitemare3D Windows1.10 — pass123: object lookup and contact removal

## Finding
Original `1010:CEF0` finds an object record only when its stored cell far-pointer WORDs AND its class byte match the queried cell. Original `1010:CF4A` clears the cell's object byte and bit0 in record flags without unlinking or compacting records. Both routines and lookup→remove→lookup sequences executed without any simulated callees.

This continues the contact-object path called by84F4 throughCF60. Evidence is original Win16 EXE microexecution against the preserved Ghidra12.2 native export, not a fresh Ghidra or live game/Win16 run. Workspace maintenance removed transient inputs; the original EXE and full native listing were restored from the saved pass122 archive before this analysis.

## Behavior model
`CEF0(cellOffsetWORD,cellSelectorWORD)` is far cdecl and returns a far pointer DX:AX on a hit, or0:0 on miss. In this fixture DS=SS before entry.

```text
count = signed16(DS.word[7E58h])
for i=0 while i<count:
    r = NE9:word(6D66h + 1Ch*i)
    if r.word[0Ch]==cell.offset and r.word[0Eh]==cell.selector:
        if r.byte[0]==cell.byte[1]: return r
return nullFar

CF4A(cellFar,recordFar):
    cell.byte[1] = 0
    record.byte[5] &= FEh
```

The native routine temporarily changes DS to the record selector; later loop comparisons explicitly use SS:7E58. On positive-path return it sets DS=SS. These conventions should not be silently generalized to callers with arbitrary DS/SS or self-mutating counts.

Unlike the earlier1296 lookup, CEF0 has a third class check and returns explicit null on miss. Neither lookup normalizes the queried far-pointer representation. A bit0-cleared record is not automatically excluded by CEF0; its class match is still required. For tested nonzero classes, clearing the cell byte makes the subsequent lookup miss. For synthetic class0, the cleared byte remains equal, so the record is found again. This is not a demonstrated gameplay bug or a claim that class0 is a collectible.

## Implementation-ready findings
Use record stride28 and compare all three identity components. Keep exact far-pointer representation. Preserve first-match selection and explicit null miss. Implement removal as two writes rather than deleting an array element or decrementing count. Do not add a record-flag filter to a faithful CEF0 reconstruction without separate caller-side evidence. Mark class0 gameplay reachability asTBD.
