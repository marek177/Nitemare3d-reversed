# Nitemare 3D – RE-RUNTIME NEXT: GUARD 41 smrť, RNG #16–18, skóre +100 a zmazaný mapový marker

**Dátum:** 19. október 2026  
**Typ dôkazu:** nový skutočný runtime pôvodného DOS V1.2 v upravenom DOSBox-X Advanced History v3.  
**Výsledok:** úplný ohraničený trace od inštrukcie nulovania HP GUARD 41 až po mapový zápis na konci death handlera. Zachytené pôvodné strojové inštrukcie, pamäťové operácie a pred/po snapshoty. **Žiadny zásah debuggerovým `SM` do hernej pamäte, EXE ani RNG.**

Bežala prirodzená `DEMO.1`, originálny nepatchovaný herný kód, DOSBox-X `core=normal`, `cycles=fixed 75000`, Linux/Xvfb, zvuk vypnutý. Dôkazový ZIP **neobsahuje** komerčné herné dáta ani spustiteľné súbory. Debugger zaznamenal vstup na prvom smrteľnom zápise `0CC6:1335` bez prepisovania hernej RAM.

**Mapa adresovania:** pri tomto DOS V1.2 behu zodpovedajúce statické offsety v 512-B MZ sú `file_offset = 0x200 + CS*16 + IP - 0x8240` (runtime load base segment `0824`). Neprenosné automaticky na V2.0 alebo iné relokácie. Tieto konkrétne opcode kotvy verifikuje `verify_guard41_death.py --unpacked ...` proti originálu.

## 3. Zistené výsledky – priamo pôvodný runtime

| Pole | Pred | Po | Originálny writer |
|---|---:|---:|---|
| GUARD41 HP `+0x10` | 111 (`6F`) | **0** | `0CC6:1335` |
| GUARD41 byte `+0x00` | `10` | `29` | `0CC6:087D` (16-bit zapisuje `0410→0429`) |
| GUARD41 word `+0x06` | 2 | 3 | `0CC6:0893` |
| GUARD41 byte `+0x0B` | `06` | `00` | `0CC6:08A1` |
| GUARD41 byte `+0x0C` | `05` | `09` | `0CC6:089A` |
| Skóre `DS:40DE/40E0` | 0 | **100** | `0CC6:13B1` a `13B5` |
| Prepojený mapový bajt (lineárne `0x2B421`) | `A5` | **00** | `0CC6:13D1` |

Identita GUARD index41: `SI=0x2A78`, začiatok tabuľky `0x264E`, stride `0x1A=26`, index `(0x2A78-0x264E)/26=41`. Pool segment `264B`. Skóre má DS `2BBF`; fyzické slovo `0x2FCCE` sa zmenilo `0000→0064`, vyššie slovo `0x2FCD0` zostalo `0000`.

Po zapísaní skóre a po mapovom commite zostáva GUARD snapshot totožný pre všetkých meraných 64 bajtov. Z toho **nevyplýva**, že celý jeho ďalší animation/OBJECT lifecycle je dokončený.

## 4. RNG #16, #17, #18 – presne vykonané, bez medzery

Rekurencia `state' = (state * 214013 + 2531011) mod 2^32`, `AX=(state'>>16)&0x7FFF`:

| RNG | Stav pred | Stav po | AX | AX mod 7 | Rozhodnutie vykonanej vetvy |
|---|---|---|---:|---:|---|
| #16 | `A6E9C9A6` | `81EB59D1` | 491 | 1 | `103C:1BF5 JE → 1BC9`, odmietnuté |
| #17 | `81EB59D1` | `0BB31550` | 2995 | 6 | `103C:1BF5 JE → 1BC9`, odmietnuté |
| #18 | `0BB31550` | **`AEA69ED3`** | 11942 | 0 | `JE` nepoužitý, pokračovanie `103C:1BF7`, prijaté |

Pri všetkých troch odberoch boli pozorované dvojice 16-bitových zápisov nízkej a vysokej polovice RNG na lineárnych adresách `0x2E096/0x2E098` z originálnych inštrukcií `19E6:3213/3216`. Posledný DS snapshot obsahuje `AEA69ED3`.

**Novinka oproti RNG17 balíku:** RNG #17 je konečne naozaj vykonaný (nielen breakpoint/predpoveď) a máme aj plne pozorovaný RNG #18, finálny výber variantu, pozitívny score commit a zmazanie mapového markeru v **jedinej neprerušenej stope**.

## 5. Čo to dokazuje – a čo nie

**Dokázané pre túto konkrétnu DEMO.1 cestu DOS V1.2:** pôvodný damage handler spracoval smrteľné HP, odmietol dva animačné kandidáty, prijal tretí, upravil GUARD stav, pridal 100 bodov a vymazal prepojený mapový bajt `A5`. Údaje nepochádzajú z konverzie C alebo syntetického testu.

**Otvorené:** vizuálne dohranie celej death animácie; úplné uvoľnenie prípadného GUARD/OBJECT pool slotu; podmienky a obsah predmetového dropu; skórovanie všetkých iných tried a obtiažností; DOS V2.0 a Win16 odlišnosti; pixel/audio/timing parita; kompletné streamy ďalších DEMO RNG odberov. Mapový marker `A5→00` ešte nie je dôkazom všetkých cleanup writerov v iných segmentoch.

## 6. Verifikácia bez znovuspustenia emulátora

```bash
python3 verify_guard41_death.py
# Voliteľne silnejšie pôvodné opcode + fingerprint dôkazy:
python3 verify_guard41_death.py \
    --packed /sukromne/N3D.EXE \
    --unpacked /sukromne/N3D-12.exe \
    --emulator /sukromne/dosbox-x-n3d
```

Prvý príkaz nezávisle prepočíta SHA-256, prejde **všetkých 12 707 udalostí v poradí**, identifikuje presné CPU writery, 3 RNG kroky, dve odmietnutia a jedno prijatie animácie, a skontroluje všetky pred/po binárne snapshoty. Pri druhom porovná aj originálne binárky a opcode kotvy.

`repro/capture_guard41_death.py` uvádza metódu pôvodnej exekúcie, ale lokálne cesty k emulátoru a komerčnej hre treba nastaviť pre vlastné prostredie. Scripted debugger navádza **klávesnicu a breakpointy**, nepatchuje gameplay/RNG.
