## Implementované

- `src/renderer/ImgTextureSampler.hpp` (nový): priame rozlíšenie wall/object slot → offset rámca; pixely sú *column-major*, teda `pixels[x * height + y]`.
- `src/renderer/Raycaster.{hpp,cpp}`: ukážkové DDA vykreslenie skutočných paletových IMG stenových textúr. Chýbajúce alebo nulové sloty zostávajú ako diagnostická jednofarebná náhrada.
- `renderPushables`: vzorkovanie príslušného `objectSlotOffsets[objectId]` podľa pôvodných obrázkov; pixel index `0x1F` je priehľadný. Týka sa zatiaľ len PUSH objektov v jednoduchom rendereri, nie všetkých GUARD/OBJECT sprite režimov.
- `src/main.cpp`: predá `data.episode().images` rendereru.
- `tests/img_texture_sampler_test.cpp` (nový, syntetické dáta): sloty, rozloženie po stĺpcoch, priehľadnosť, bezpečné kraje UV, kontrola framebuffer fallback versus textúra.
- `CMakeLists.txt`: nový CTest.

**Neznamená to pôvodný DOS 1:1 renderer.** Používame jednoduchý DDA výpočet a zatiaľ len prvý frame slotu. Chýba presný vector/span projektor, animácie, špeciálne dvere, sprite GUARD AI, shading, odlišné smery/textúry, clipping a HUD; IMG široké 128 px sa momentálne približne mapujú na jeden DDA wall face.

## Nový zistený problém

Na E1M1 pôvodný zjednodušený `LevelState::wallAllowsMovement` a DDA renderer vykreslia do popredia aj ID `0xF0` a `0xF1`, v `WALLS.1` pomenované `TURN`. IMG pre tieto ID nemá stenovú textúru. **Náš DDA preview teda zobrazuje oranžový diagnostický blok**, nie preukázanú originálnu stenu. Bez dôkazu z pôvodného property-table/renderer kontraktu som collision/marker logiku teraz nemenil. Ďalšou úlohou je oddeliť neviditeľné mapové markery a korektný collision/occlusion režim pre všetky triedy.

## Reprodukcia

Príklad, ak máš nainštalované SDL3 (vývojové CMake súbory):

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug \
  -DN3D_ENABLE_SDL3=ON -DN3D_FETCH_SDL3=OFF \
  -DSDL3_DIR=/path/to/SDL3/lib/cmake/SDL3 \
  -DN3D_TEST_DATA_DIR=/path/to/dos-data
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software SDL_AUDIODRIVER=dummy \
  build/nitemare3d --data /path/to/dos-data --episode 1 --level 1
```

Priečinok `dos-data` musí obsahovať skutočné `MAP.1–3`, `WALLS.1–3`, `OBJECTS.1–3`, `GAME.PAL` a `IMG.1–3`. Pri nových nahraných súboroch `IMG(20261019-...)` ich iba premenuj/kopíruj ako `IMG.1`, `IMG.2`, `IMG.3`; zvyšok dát zostáva pôvodný. IMG ani originálne DOS dáta NIE sú súčasťou distribučných ZIP balíkov. Linuxová SDL3 knižnica v balíku je zostavená pre headless dummy/software a nemá X11/Wayland backend.

GitHub repozitár nebol aktualizovaný; úpravy sú len v pracovnej kópii a patchi.

## Predpoklad patchu

Súbor `Nitemare3D_IMG_Texture_Integration.patch` je vytvorený **voči predchádzajúcej opravenej Linux pracovnej kópii so spracovaním GAME.PAL** (`Nitemare3d-reversed-realdata`), nie voči neopravenému GitHub `main`. Ak chceš začať rovno z originálneho GitHub ZIP, použi kompletný aktuálny zdrojový ZIP v tomto výstupe alebo najprv aplikuj staršie Linux/GAME.PAL opravy. Overil som `patch -p1 --dry-run` voči uvedenej opravenej kópii.
