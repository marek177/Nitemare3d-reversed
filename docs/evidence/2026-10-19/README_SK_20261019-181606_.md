# Nitemare 3D – RE-RUNTIME NEXT: RNG #11–#17, GUARD 41 death branch

**19. október 2026.** Pôvodný **DOS V1.2** (`N3D.EXE`, SHA-256 `32029326da3e9e356f5d17ca98e420dee178486f1384af8e7ccc662671c12511`) spustený nezmenený v modifikovanom DOSBox-X Advanced History v3 (SHA-256 `1967f583ccbe6a25a58318dc1ddba8fa48a7b697f6eb4b4c04158bbeaa258db3`), Linux/Xvfb, `cycles=fixed 75000`, zvuk vypnutý. Autentická `DEMO.1`, ovládanie klávesnicou. **Hra, RNG ani GUARD RAM neboli patchované.**

## Čo je nové a pôvodným CPU doložené

1. **RNG #11 callsite:** V skutočnom 256-B stack dumpe RNG #11 pri `SS:SP=2BBF:E6D6` ležia návratové adresy `17B3:019B` (wrapper) a **`0CC6:0A43`** (GUARD planner). `SI=2A78` patrí GUARD index41 (index od nuly; báza `0x264E`, stride `26`). Oproti staršiemu pokusu stack dump existoval – vytvoril sa pod názvom `:E6C0 0100`.
2. **RNG #11→#12:** Kompletný originálny `USER_STOP` záznam s **56 CPU inštrukciami, 159 pamäťovými čítaniami a 15 zápismi**. `DF90722B → 1649B442`, AX `5705`. GUARD41 `+0x14` Y vektor **`00→F8`** (−8), následne ďalšie RNG volanie na `0CC6:0AD7` s návratom **`0CC6:0ADC`**. Dôkaz `trace/rng11_to_rng12.n3dt`.
3. **RNG #12:** Originálna CPU stopa začínajúca vstupom RNG12 potvrdzuje `1649B442 → 6DF109FD`, AX `28145`. Nasleduje zápis GUARD41 `+0x06` časovača **0→9** a `+0x0B` stavu **05→06**. Pri kontrole desiatkovej hodnoty, `28145 % 8 + 8 = 9`. Záznam je prvých 1000 udalostí veľkého (size-limit) behu; nepredstavuje súvislý interval až po RNG13.
4. **RNG #13/#14:** Stacky potvrdzujú plánovanie GUARD index43 (SI `2AAC`, návrat `0CC6:0A43`) a index40 (SI `2A5E`, ten istý návrat). CPU prefixy potvrdzujú príslušné nové RNG stavy a ich lokálne `GUARD.state=06` writery. Medzi nasledujúcimi breakpointmi je viacmiliónový CPU interval, preto predčasne skončené 512-MB tracey **nepočítame** ako plnú kontinuálnu históriu.
5. **RNG #15 → smrteľné poškodenie GUARD41:** druhý, nezávislý `USER_STOP` CPU trace má **147 CPU, 395 READ, 39 WRITE**. RNG15 `C1BBB05F→A6E9C9A6`, AX `9961`; damage handler vracia `AX=0x00A5` (**165**). Pôvodný engine zapísal **GUARD41 HP=111→0** na fyzickej `0x28F38`, `0CC6:1335`, a volá reakčný descriptor handler. Je to skutočné vykonanie originálu, nie simulačný model. Neznamená to ešte celý death/drop/score closure.
6. **RNG #16 → rejection loop → #17:** skutočne vykonané RNG16 `A6E9C9A6→81EB59D1`, AX `491`. Jeho animačný výsledok je odmietnutý, CPU vykonalo `103C:1BF5 JE` späť na RNG callsite `103C:1BC9`. Potvrdil sa breakpoint **RNG17** so seed pred vstupom `81EB59D1`. Predikcia až po budúcom vykonaní #17 je `0BB31550`, AX=2995; tento post-state #17 **nebol vykonaním overený**.

## Proveniencia a hranice

- `trace/rng11_to_rng12.n3dt` a `trace/rng15_to_rng17.n3dt` sú **úplné pre uvedené ohraničené úseky**, ukončené USER_STOP. Druhý záznam sa končí pred vykonaním RNG17, po jeho volacom wrapperi.
- `trace/rng12_prefix_1000events.n3dt` atď. sú iba prvých 1000 udalostí autentických veľkých behov, ktorých plná história skončila na **SIZE_LIMIT (512 MB)**. Ich použitie je obmedzené na skutočne zahrnuté inštrukcie, najmä lokálne GUARD writery.
- `stack/rngXX_stack_256.bin` sú originálne 256-B dumpty `SS:...`, zdokumentované pri konkrétnych breakpoin­toch. Snímky `screenshots/rngXX.png` zobrazujú CPU/RNG pred vstupom, nie po vykonaní funkcie.
- Pôvodné N3D EXE a komerčné dáta **nie sú** súčasťou tohto dôkazového balíka.
- Nie je potvrdený jeden neprerušený trace medzi všetkými RNG #11–#17, ani prirodzená 1:1 parita remaku, Win16, audio alebo pixel-zero-diff.

## Ďalší RE-first krok

Staticky uzavrieť writer/reader chain GUARD41 death/animation/score po `0CC6:1335` a dostupnosť descriptorov v rejection loopu. Potom cielený originálny runtime RNG17+ až po prijatie animácie a death outcome. Pri ďalších 2.8M-inštrukčných odstupoch nahrávať iba CPU (bez nevyhnutných READ udalostí) alebo používať breakpointovo obmedzené krátke logy; 512MB limit inak skončí pred ďalším RNG breakpointom.
