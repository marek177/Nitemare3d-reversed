# Pass 70 — video-mode controller and reciprocal table

## Finding
Confirmed for six distinct DOS binaries: command0 saves the current BIOS video mode, initializes graphics, checks that BIOS reports13h, then builds511 reciprocal dwords. Command1 restores a saved nonzero mode without clearing it. Other commands return without action. Supplied1.8/1.9 are identical binaries.

## Behavior model
For command0, BIOS INT10 AH0f returns a mode byte that is saved exactly, including zero. Then the original graphics initializer is called. A second AH0f result must have AL13h; otherwise a fatal routine receives the error format pointer and returned mode. On success the reciprocal initializer writes contiguous little-endian32-bit signed-division results with numerator0x400000 and positive denominators1..511. Values are positive, so signed division matches integer floor. No table entry for denominator0 is written; there are exactly511 entries and no writes outside that range in the fixtures.

For command1, read the saved byte. If nonzero, BIOS INT10 AH00 requests that exact mode; if zero, no BIOS call occurs. The saved byte is retained. Thus zero is also a suppress-restore sentinel even though BIOS mode0 can be a real mode. This is a local semantic observation, not evidence of a user-visible failure in normal startup. Commands2 andffff were verified as no-ops. No general return-value contract is asserted.

## Verification
84 passing fixtures (14 per distinct binary): enter command with previous modes0/3/7/13h and reported result13h/03h; restore with saved0/3/7/13h; unknown commands2/ffff. Each restore/no-op fixture runs twice in the same state. All successful enter cases execute the original reciprocal initializer and compare every dword plus sentinel bytes before/after. Failed enter and other commands preserve the table sentinel. Original controller and reciprocal code execute unchanged.

Mocked boundaries: BIOS INT10 responses/requests, fatal handler stops, and the graphics initializer call is skipped at its call site after checking saved state. That initializer was separately tested in pass69; this pass does not claim an integrated BIOS/VGA startup. The far return generated by PUSH CS before the skipped near call is removed correctly by the harness. No actual BIOS, VGA scanout, palette or complete game behavior is proven.
